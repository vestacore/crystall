# **Core Terminology Glossary**

## **1. Semantic Spiral & Phase-Level Terms**

### **Semantic Spiral**

A layered process of cognitive unfolding where the system moves through a sequence of phases, each structuring a different mode of interpretation and transformation of the user’s intent. The spiral represents *ordered variability*: stable in structure, flexible in execution.

### **Phase**

A named segment of the semantic spiral, such as `Learn`, `Understand`, `Connection`, `Service`, `Knowledge`, `Evolution`, `Responsibility`.
Each phase represents a **semantic position** and defines what type of transformation is applied to the user’s intent at that point. Phases are **scenario-defined and strictly ordered**.

### **Phase Execution**

The process of running cunit → punit → funit roles for a given phase and writing the results to state.
Always produces an artifact representing that phase’s contribution.

---

## **2. Core Roles (CUNIT / PUNIT / FUNIT)**

### **CUNIT (Context Unit)**

The role responsible for shaping *semantic space*.
It configures conceptual frames, constraints, assumptions, tone, and structural patterns relevant for a phase.
CUNIT **sets the scene**.

### **PUNIT (Process Unit)**

The role responsible for shaping *semantic intention*.
It identifies questions, priorities, ordering of reasoning steps, and the system’s internal problem-decomposition topology.
PUNIT **sets the direction**.

### **FUNIT (Function Unit)**

The role responsible for *semantic action*.
It executes the configured intention in the configured space—via LLM calls, tools, retrieval, generation of artifacts.
FUNIT **produces the form**.

### **C-P-F Microcycle**

The ordered sequence `CUNIT → PUNIT → FUNIT` executed inside each phase.
Ensures separation of concerns between space, intention, and action.

---

## **3. Prompt-Level Terms**

### **PromptUnits**

A structured repository of PromptUnits.
The prompt repository separates prompts from code and makes the system fully declarative and configurable.
Acts as the *semantic memory* for process logic.

### **PromptUnit**

A single atomic configuration element in the prompts.
Contains:

* `id`
* `phase`
* `role` (CUNIT/PUNIT/FUNIT)
* `scenario`
* `tags`
* `template` (LLM prompt with variables)
* optional `priority`, `description`, schema annotations.

It is the smallest executable semantic unit in the system.

### **Prompt Selection**

The mechanism that finds the correct PromptUnit from the prompts repository using scenario, phase, role, tags, or embeddings.
Ensures deterministic behavior with room for controlled variability.

---

## **4. Scenario & Configuration Terms**

### **Scenario**

A high-level configuration defining:

* the ordered list of phases,
* branching rules,
* evaluator agents,
* specific PromptUnits allowed in this context.

A scenario is a **profile of behavior** for a particular domain (e.g. regtech QA, document reading, coaching dialogue).

### **ScenarioConfig**

The serialized definition of a scenario.
Determines the system’s execution graph without changing core engine code.

---

## **5. State Terms**

### **State**

The full structured memory of the system during execution.
Contains:

* user input and metadata,
* phase artifacts,
* sql.question graph,
* branch states,
* trace (RIT),
* final answer.

It is the **single source of truth** for all semantic operations.

### **Phase Artifact**

The structured output of a specific phase/role execution (e.g. conceptual frames, question sets, draft answer, evaluation result).
Stored under `state.<phase>.<role>.*`.

### **Trace (RIT – Resonant Interaction Trace)**

A chronological log describing:

* which PromptUnit was used,
* what inputs it received,
* what outputs it generated.

Used for introspection, debugging, ethics auditing, and reconstruction of reasoning pathways.

### **State Projection / State Summary**

A compressed snapshot of relevant state passed into prompts to prevent context overflow or drift.

---

## **6. Question Graph Terms**

### **SQL (Semantic Question Layer)**

A structured graph of all questions generated by PUNIT roles across phases.
Represents the system’s internal decomposition of the problem.

### **Question Node**

A single question with:

* id,
* text,
* dependencies,
* phase of origin,
* links to artifacts.

Forms the backbone of reasoning across the spiral.

### **Question Topology**

The dependency and priority structure of the question graph.
Controls how reasoning unfolds across phases.

---

## **7. Branching & Integration Terms**

### **Branch**

A parallel line of semantic exploration created when multiple interpretations or strategies are beneficial.
Each branch has its own:

* artifacts,
* question expansions,
* draft answer.

### **Branch State**

A self-contained substate for a specific branch stored under `state.branches[branch_id]`.

### **Candidate Answer**

A synthesized draft answer attached to a branch.
Later evaluated and integrated to produce the final answer.

### **Branch Integration**

The process of comparing and possibly merging candidate answers during the Responsibility phase.
Performed using evaluator agents.

---

## **8. Evaluation & Community Terms**

### **Evaluator Agent**

A specialized PromptUnit used in `Responsibility` phase to score candidate answers or fragments.
Examples: ethical evaluator, clarity evaluator, rigor evaluator.

### **Evaluation Schema**

The structured output of an evaluator agent, e.g.:

* `{ ethics_score: 0.8, clarity_score: 0.9, comments: "..."}`
  Used for aggregation.

### **Aggregation Policy**

The rules for selecting the best candidate (or fragments) based on evaluator scores.
Scenario-defined and modifiable without changing core code.

### **Responsibility Consolidation**

The final rewriting / harmonization of the chosen answer into a coherent, ethical, and complete output.

---

## **9. Execution Engine Terms**

### **Execution Engine / Spiral Engine**

The core system component that:

* loads ScenarioConfig,
* iterates through phases,
* executes cunit/punit/funit,
* manages state & branches,
* performs evaluation & finalization.

### **Execution Step**

A single run of a PromptUnit inside a phase.
Produces deterministic modifications to state.

### **Adapter Layer (Model Adapter)**

A thin boundary allowing the engine to call any LLM provider.
Ensures the architecture is model-agnostic.

---

## **10. Architectural Principle Terms**

### **Separation of Space, Intention, Action**

A hard constraint encoded via CUNIT/PUNIT/FUNIT.
Guarantees clean semantics and prevents prompt collapse into monolithic instructions.

### **Deterministic Skeleton / Semantic Determinism**

The system’s flow (phases, roles, trace) is deterministic even though the model outputs are not.
Ensures reliability and auditability.

### **Declarative Process Logic**

Prompts, scenarios, and evaluators live in configuration.
The engine executes them without hidden behavior.

### **Ordered Variability**

The system can vary its interpretations (branches, prompts) but only along clearly defined vectors: phase order, role semantics, scenario constraints.

### **Traceability & Inspectability**

All semantic operations are transparent, logged, and reconstructible later.
